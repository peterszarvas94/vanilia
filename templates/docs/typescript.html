{{define "doc/typescript"}}

Vanilia is written in TypeScript and ships its types. How you point TypeScript at them depends on how you load it.

Setup

From npm

Installed from npm, the package is typed with no setup.

Hosted or copied files

Keep vanilia-editor.d.ts beside vanilia-editor.js and a relative import is typed. When you import the bare "vanilia-editor" through an import map, tell TypeScript where the types are, because it doesn't read import maps:

{{template "code" `// tsconfig.json { "compilerOptions": { "paths": { "vanilia-editor": ["./static/vendor/vanilia-editor.d.ts"] } } }`}}

Script tag

The script tag build puts the same API on window.Vanilia. To type it, declare the global from the module's types:

{{template "code" `// globals.d.ts declare global { const Vanilia: typeof import("./static/vendor/vanilia-editor.js"); } export {};`}}

Typed element and events

Importing the module also types the element and its events, so there is nothing to cast. Label, icon, theme token and built-in button names autocomplete and are checked:

{{template "code" `import { setLabels, setTheme, type ToolbarButton } from "vanilia-editor"; const editor = document.querySelector("vanilia-editor"); // VaniliaEditorElement | null editor?.addEventListener("editorupdate", (event) => { console.log(event.detail.words, event.detail.active.bold); }); setLabels({ bold: "Fett" }); // "bolt" would be a type error setTheme({ accent: "#e11d48" }); // so would "acent" const signature: ToolbarButton = { name: "signature", label: "Insert signature", run: (editor) => editor.insertHTML("

— Peter

"), }; editor?.addButton(signature); editor?.exec("signature"); // exec takes commands and custom button names`}}

Exported types

The main ones are VaniliaEditorDetail, EditorCommand, ToolbarButton, ToolbarItem, LabelName, IconName, ThemeToken, ShortcutMap and UploadHandler. The full list is under Module exports.
