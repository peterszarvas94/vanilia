Layout

The toolbar attribute lists button names in order, with | between groups. Without it, the editor shows every built-in button.

The toolbar property takes the same layout as a string or an array, and reads back the items in use. null restores the default:

{{template "code" `editor.toolbar = ["bold", "italic", "|", "link"]; editor.toolbar; // ["bold", "italic", "|", "link"] editor.toolbar = "none"; // hide the toolbar editor.toolbar = null; // back to the default import { DEFAULT_TOOLBAR } from "vanilia-editor"; editor.toolbar = [...DEFAULT_TOOLBAR, "|", "signature"]; // default plus a custom button`}}

A name with no button yet is skipped, and shows up once a custom button with that name is added, so a layout can list buttons you add later. Keyboard shortcuts work whether or not their button is shown.

Selection menu

Selecting text opens a small menu with bold, italic, underline, strike, code and link. Change it with bubble-menu (or the bubbleMenu property), using the same syntax. It can hold any button, custom ones included. "none" turns it off.

Custom buttons

A custom button has a name, a label and a run() function. Add it to one editor with addButton(), or to every editor on the page with defineButton():

{{template "code" `const editor = document.querySelector("vanilia-editor"); editor.addButton({ name: "signature", label: "Insert signature", icon: '', // or the name of an icon text: "Sign", // optional visible text shortcut: "Mod+Shift+S", // Mod is ⌘ on macOS, Ctrl elsewhere run: (editor) => editor.insertHTML("

— Peter

"), }); editor.removeButton("signature");`}}
FieldDescription
nameRequired. Letters, digits, _ and -; can't be a built-in name. Use it in layouts and with editor.exec(name).
labelRequired. Tooltip and accessible name.
run(editor)Required. Runs on click, on the shortcut and on exec(name).
iconA built-in icon name, a name registered with setIcons(), or trusted markup (anything containing <).
textVisible text, after the icon or on its own.
shortcutDefault keyboard shortcut, like "Mod+Shift+S" or "Mod+Alt+1", or an array of them. Shown in the tooltip; setShortcuts() can change or remove it by the button's name. See Keyboard shortcuts.
isActive(editor)Pressed state, re-checked whenever the selection or content changes.
isEnabled(editor)Return false to disable the button. Re-checked like isActive.

Where a custom button shows up: with the default toolbar, in a group at the end; with a toolbar or bubble-menu layout, wherever its name appears. Inside run() you have the whole element API (insertHTML, insertText, getSelectedText, exec, ...) and, for formatting the API doesn't cover, the underlying editor.squire. A button for the superscript command, which has no built-in button:

{{template "code" `import { defineButton } from "vanilia-editor"; defineButton({ name: "sup", label: "Superscript", icon: "superscript", // a name registered with setIcons(), see below shortcut: "Mod+.", isActive: (editor) => editor.isActive("superscript"), run: (editor) => editor.exec("superscript"), });`}}

For icons by name, register the markup once with setIcons({ superscript: "<svg>...</svg>" }). Formatting and inserted markup only keep the tags the editor knows (headings, lists, b, i, u, s, code, sub, sup, links, images, ...); anything else is stripped.

Your own toolbar

toolbar="none" hides the built-in toolbar. Your buttons call editor.exec() and read the active state from ve:update. The selection menu, image handles, link and image popovers and find & replace keep working.
